# Platform overview

Zip sits between the people who need to buy something and the systems of record that account for it. A requester describes what they need, Zip routes that request to the right approvers in legal, IT security, finance, and procurement, and the approved result flows into your ERP as a purchase order. Everything downstream, from the vendor invoice to the payout, stays linked back to that original request.

This space describes the foundation the rest of the product is built on: the core object model, the organization structure that scopes it, and the administrative controls that govern access. Read it first if you are configuring Zip for the first time, or if you need to understand why a record behaves the way it does in [Intake-to-Procure](https://app.gitbook.com/s/BMSPlYB6zBpUu9WDNW3q/) or [Procure-to-Pay](https://app.gitbook.com/s/uvWZCHh4l0VWI5nRG3c4/).
