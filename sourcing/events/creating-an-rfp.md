# Create an RFP

Build the whole event before you invite anyone. Suppliers see the event as a single package, and changing the question set after suppliers have started responding forces them to redo work and weakens any comparison you draw.

{% stepper %}
{% step %}
## Start the event

On the **Sourcing** page, select **New event** and choose **RFP**. Give it a name, an owner, and a submission deadline. If the event came from an intake request, link the request so spend and savings reconcile later.
{% endstep %}

{% step %}
## Write the overview

Describe the scope, the business context, and the evaluation approach. State how responses will be scored and when you expect to award. Suppliers write better proposals when they know what you are weighing.
{% endstep %}

{% step %}
## Build the question set

Add questions grouped into sections, for example company background, solution, implementation, security, and support. Use structured question types where you intend to compare answers mechanically: single select, multi select, number, date, and file upload. Reserve long text for the questions where the narrative genuinely matters.
{% endstep %}

{% step %}
## Add requirements

Requirements are statements the supplier confirms it meets, does not meet, or meets with a workaround. Mark the ones that are mandatory. A supplier that fails a mandatory requirement can be disqualified without scoring the rest of its response.
{% endstep %}

{% step %}
## Build the pricing sheet

Define the line items you want priced, the units, and the quantities. Fixing the structure is what makes bids comparable. Include the currency you want quoted in, and say whether pricing should be exclusive of tax.
{% endstep %}

{% step %}
## Set the scoring model

Assign a weight to each section and, within a section, to each scored question. Weights should total 100. Decide now whether price is scored automatically from the pricing sheet or judged by evaluators.
{% endstep %}

{% step %}
## Attach documents and publish

Attach specifications, your standard terms, and any security questionnaire. Review the supplier preview, then publish.
{% endstep %}
{% endstepper %}

{% hint style="warning" %}
Set the deadline in the supplier's terms, not yours. Zip shows suppliers the deadline in their own time zone, but a Friday afternoon deadline still lands on a weekend somewhere. Give suppliers enough working days to involve their own legal and pricing teams.
{% endhint %}

## Reusing an event

Save a completed event as a template. Templates carry the question set, requirements, pricing structure, and scoring weights, but not suppliers or responses. Most procurement teams maintain a small number of templates by category rather than building each event from scratch.

<details>

<summary>Can I attach our standard contract to the RFP?</summary>

Yes, and it is usually worth doing. Suppliers that flag redlines during the event rather than after award save weeks of contracting. Redlines returned with a bid can be routed into [AI Contract Orchestration](https://app.gitbook.com/s/DeZIgDtBPmTV8Lg8mf2S/) for review alongside the commercial evaluation.

</details>

<details>

<summary>What happens if I edit a published event?</summary>

Suppliers are notified of the change and the affected answers are flagged as needing review. Substantive changes usually warrant extending the deadline. Every edit after publication is recorded on the event.

</details>
