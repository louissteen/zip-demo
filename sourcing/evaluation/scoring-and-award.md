# Score and award

Scoring turns evaluator judgment into a number you can defend. The model is set before the event opens, so nobody is choosing the weights after seeing the bids.

{% stepper %}
{% step %}
## Score as an evaluator

Open the event and go to your assigned sections. Score each scored question on the defined scale and add a comment explaining the score. Comments matter more than the number when someone questions the outcome later.
{% endstep %}

{% step %}
## Review the aggregate

The event owner sees weighted scores by section and in total, with each evaluator's contribution visible. Look for wide divergence between evaluators on the same question. That usually means the question was ambiguous, not that one evaluator is wrong.
{% endstep %}

{% step %}
## Reconcile divergence

Hold a calibration discussion for the questions where evaluators disagree materially. Evaluators can revise scores; revisions are recorded with the original.
{% endstep %}

{% step %}
## Prepare the award recommendation

Zip assembles a summary: the ranked suppliers, the scores by section, the normalized pricing, and the requirements each supplier met. Add your rationale, particularly if you are not awarding to the top-scoring supplier.
{% endstep %}

{% step %}
## Route the decision for approval

Submit the recommendation. The award approval chain is built the same way an intake approval chain is, using the event value, category, and any policy conditions your organization sets.
{% endstep %}

{% step %}
## Award and notify

Once approved, select **Award**. The winning supplier is notified and the event moves to **Awarded**. Unsuccessful suppliers are notified too, with as much or as little detail as your policy allows.
{% endstep %}
{% endstepper %}

## Splitting an award

An event can be awarded to more than one supplier, either by line item or by region. Each awarded supplier gets its own award record and its own downstream contract. Split awards are common where you want a primary and a secondary supplier for continuity.

{% hint style="info" %}
Awarding is a decision, not a commitment. The commitment is the contract and the purchase order. Nothing is owed to the winning supplier until those exist.
{% endhint %}

## What happens after the award

Three things typically start at once.

**Contracting.** The negotiated terms move into [AI Contract Orchestration](https://app.gitbook.com/s/DeZIgDtBPmTV8Lg8mf2S/), where the agreement is drafted or redlined and routed for legal approval.

**Onboarding.** If the winning supplier has no active vendor record, [Supplier Onboarding](https://app.gitbook.com/s/QStVF3i0EZksxOR4LHvB/) starts so tax and banking details are collected before the first invoice.

**Purchasing.** The linked intake request resumes with the awarded price, and the purchase order is issued against the awarded amount.

## The award record

The event retains everything: the published question set, every response, all scores and comments, the clarifications, the recommendation, and the approvals. That record is what you produce when an unsuccessful supplier asks why it lost or an auditor asks how the decision was made.
