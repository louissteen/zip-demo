# Asking a question

Requesters reach the Concierge from the **Ask Zip** entry point in the Zip web app, or from the Zip app in Slack or Microsoft Teams if your administrator has connected one. The conversation is the same in all three places, and it carries the requester's own permissions.

## Ask a question and act on the answer

{% stepper %}
{% step %}

## Open the Concierge

In Zip, select **Ask Zip** from the top bar. In Slack or Teams, send a direct message to the Zip app or mention it in a channel where the app is installed.

{% endstep %}
{% step %}

## Describe what you want to buy

Write the question the way you would ask a colleague. "I need a design tool for six people" works as well as a formal request. You do not need to know the category, the form name, or the approval path.

{% endstep %}
{% step %}

## Review what the Concierge found

The Concierge answers with the relevant policy, and it names any existing vendor record or contract that already covers what you described. Each answer cites the record or policy section it came from, so you can open the source before you act on it.

{% endstep %}
{% step %}

## Start the request

If a new request is the right next step, select **Start request**. The Concierge opens the correct intake form and pre-fills the fields it can already answer from the conversation: category, vendor, estimated amount, and description. Review those values before you submit, because they become the basis for routing.

{% endstep %}
{% step %}

## Track it from the same thread

Come back to the same conversation to ask where the request is. The Concierge reads the live approval chain and reports the current step and assignee.

{% endstep %}
{% endstepper %}

{% hint style="success" %}
Pre-filled fields save the most time on categories with long intake forms. If a pre-filled value is wrong, correct it in the form rather than in the chat. The form is the record of what you submitted.
{% endhint %}

## What the requester sees on a match

When the Concierge finds an existing contract or an approved vendor covering the request, it says so before offering the intake form. The requester can add themselves to an existing agreement, raise a change to it, or continue with a new request if the existing one does not fit. Duplicate spend is easiest to prevent at this moment, before a form is filled in.

## If the Concierge cannot answer

The Concierge says it does not have an answer rather than guessing, and offers to send the question to your procurement team. See [Handoff to a human](handoff-to-a-human.md) for what happens next and how the reply comes back.

For the full intake path once a request exists, see [Intake-to-Procure](https://app.gitbook.com/s/BMSPlYB6zBpUu9WDNW3q/).
